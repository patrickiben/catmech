Use recorded values without trusting them

Records contain mistakes, and checking every one against its source is expensive. catmech, an R package, uses a checked sample of records to fill in plausible checked values for the rest, many times over, and carries that uncertainty into the answer.

      The problem
      
    
      Two poor options, and a third
      
    
      
      
      Trust the recorded values
      Precise, and sometimes the best choice. But errors that grow with the value or differ between groups go straight into a slope, and the interval does not know it. A constant offset moves only the intercept.
      
      
      Use only the checked records
      Honest, but it throws away most of the data, so intervals get wide.
      
      
      Learn from the checked records
      Use the audit to learn how recorded values relate to checked ones, then fill in the rest several plausible ways, carrying the uncertainty forward. This is what catmech does.
      A small audit does not always beat trusting the records, and nothing tells you in advance when it will.
      
    
      
  
      

  
      
    
      Words used here
      
    
      
    Eight terms, from recorded value to oracle
    
      
    
      
      
      Recorded value
      What the record says, such as a self-reported weight. Most records have one, and some are wrong.
      
      
      Checked value
      The value confirmed against the source, such as a measured weight. The package calls it the reference.
      
      
      Audit
      Checking a subset of records. The checked records are the audited rows.
      
      
      Multiple imputation
      Filling in each missing checked value several plausible ways, analyzing each copy, then combining.
      
      
      Interval
      The 95% range around an estimate. It should contain the true value 95% of the time.
      
      
      Coverage
      How often, across repeated studies, the intervals actually contain the true value.
      
      
      Typical error
      Root mean squared error: how far estimates land from the truth, on average.
      
      
      Oracle
      A benchmark that uses every checked value. No real audit has it.
      
    
      
    
      
    
      
  
      

  
      
    
      How it works
      
    
      Learn, fill in, analyze, combine
      
    
      The recommended start is linear imputation given the recorded value. catmech_reference(..., use_recorded = TRUE) learns and fills in; catmech_pool_lm() analyzes and combines. Without use_recorded = TRUE, catmech_reference() leaves the recorded value out: the method called "fill in without the recorded value" below.
      
    
      



    
      
    
      
      
      Learn
      On the audited rows, fit a straight-line regression of the checked value on the recorded value and the variables you list in predictors, which should include your analysis outcome.
      Assumes the audit picked rows at random, or by the recorded value or other variables in the model, and that checked values are exact.
      
      
      Fill in
      For each unaudited row, draw a checked value from that model, with its uncertainty. Repeat to make several completed copies, 20 in the examples.
      Assumes a straight line in the recorded value, normal scatter of constant size, and independent rows. Gross errors break the line. Rows with no recorded value are filled in from the other variables alone.
      
      
      Analyze each
      Run your regression on every completed copy, exactly as you would on clean data.
      Clustered audits need a cluster-robust variance here: catmech_pool_lm(cluster = ).
      
      
      Combine
      Pool the copies with Rubin's rules. The interval adds how much the copies disagree to the usual sampling error.
      Result: one estimate and interval, plus a log of every value replaced and why.
      
    
      
  
      

  
      
    
      A worked example
      
    
      Self-reported weight in NHANES
      
    
      Public survey data with both a self-reported and a measured weight. Keep the measured weight on a random 25% of people, as an audit would, and estimate how systolic blood pressure changes per kg of weight.
      
    
      
      
      3908 people
      in the evaluation pool; 977 audited.
      
      
      65.4% off by over 1 kg
      624 of the 954 audited people with both weights. The median absolute difference is 1.7 kg.
      
      
      0.126 mmHg per kg
      Filling in from the recorded value, against 0.127 with every measured weight.
      
    
      
    
      
      
      Five ways to answer, on the same audit
      
      
      Estimate and 95% interval. The dashed line is the answer with every measured weight.
      
      
      
        
      Every measured weight0.127 (0.100 to 0.154)
      
        
      Fill in from the recorded value0.126 (0.097 to 0.155)
      
        
      Trust the recorded value (3844 with one)0.108 (0.079 to 0.137)
      
        
      Fill in without the recorded value0.108 (0.047 to 0.169)
      
        
      Audited rows only0.141 (0.082 to 0.199)
      
      
      
      
      Filling in from the recorded value landed next to the full answer with an interval about as narrow. Trusting the self-reports was just as narrow but low. The two methods that ignore recorded values were about twice as wide. This is one audit, an illustration, not a study.
      
    
      
    
      
      The code
      
      

      install.packages(c("digest", "jsonlite", "mice", "posterior", "truncnorm", "yaml"))
install.packages(".", repos = NULL, type = "source")   # from the repository directory

library(catmech)
d <- read.csv("validation/real-data/nhanes-pool.csv")
d <- d[d$split == "evaluation", ]
set.seed(1)
audited <- sample(nrow(d), nrow(d) / 4)
d$audit_kg <- NA_real_
d$audit_kg[audited] <- d$reference_kg[audited]

# 1. Read what the audit shows. This fits no model.
catmech_recording_audit(d, "recorded_kg", "audit_kg", by = "sex", agreement_tol = 1)

# 2. Fill in from the recorded value. In each completed copy, recorded_kg holds
#    the measured weight where audited and a drawn value elsewhere.
fit <- catmech_reference(d, "recorded_kg", "audit_kg",
  predictors = c("age", "sex", "race", "height", "sbp"),
  use_recorded = TRUE, m = 20, seed = 123)
catmech_pool_lm(fit, sbp ~ recorded_kg + age + sex + race + height)

      Where it fails
      
    
      Coverage should be near 95%. These were not.
      
    
      Coverage of linear imputation in the package's own tests. Each card names what broke it.
      
    
      
      
      64.7%
      Gross errors
      Some values ten times too large, in simulation. The error model, catmech_contamination(), reached 94.0% there.
      
      
      38.0%
      Noisy checked values
      When the audit's own values carry noise, in simulation.
      
      
      74.0%
      Audit chosen by the truth
      Records picked because of their true value, with errors present, in simulation.
      
      
      81% to 86%
      Clustered errors
      On the worst items of a Rwanda health-facility recount at a 25% audit, even with a cluster-robust variance, against 94% to 97% for the recount. An item is one reported count, such as early antenatal visits.
      
      
      An audit that finds no errors
      If every audited record agrees, it keeps the recorded values with no added uncertainty and warns you. A small audit can simply miss rare errors.
      
      
      Try these in the simulator
      Decimal slips with a small audit, and an audit that finds nothing, are presets in the audit simulator.
      
    
      
  
      

  
      
    
      What the tests found
      
    
      Each test had a rule written before it ran
      
    
      Where a test's rule named a verdict, the chip shows it; the first two chips summarize findings. The validation folder in the repository holds each plan and write-up.
      
    
      
      
      Finding
      Public data with real recording differences. At a random 25% audit, over 1,000 cohorts of 600, linear imputation matched or beat the package's own error model: typical error 0.0286 against 0.0308 on ClinicalTrials.gov, and 0.0409 against 0.0408 on NHANES. The model could not tell which records were wrong.
      
      
      Finding
      Keeping the recorded value pays, against discarding it. Intervals about half as wide (0.102 against 0.205 on ClinicalTrials.gov, and 0.154 against 0.297 on NHANES), with coverage near the oracle's. Against simply trusting the recorded value, a small audit often did not reduce error: at a 25% audit of a real recount, the recorded value alone had lower error than every audit-based method on 6 of 11 items.
      
      
      Inconclusive
      A real audit, a health-facility recount in Rwanda. At a 25% audit, where a reported slope differed from a recount of that one item, the error model's intervals covered 35% to 72%, against 90% to 97% for the recount. Only one reported slope, for antenatal 4th visits, clearly differed.
      
      
      Partial
      The clustered imputation option, twice. Under the variance then in use, it raised coverage on common items (from 79.6% to 91.0% on early antenatal visits) and had 4% to 5% more error on rare ones. The verdict sits within simulation noise of NO-GO. Use it only when the audited value is the outcome.
      
      
      Mixed
      A second health system. Errors barely clustered there, and the clustered option added little.
      
      
      Keep, narrowly
      The clustered option against outside methods. In a rerun after the planned comparison, mice with the same model matched its accuracy once a default that can drop the recorded value was off.
      
      
      Keep, narrowly
      Against setups written by fresh AI agents that saw no results. None met the rule, but the best looks better than the option on most measures, so the option is not the best available.
      
      
      Not adopted
      Separate within-site and between-site slopes. They helped when the audited value was a predictor, and had 1.258 times the option's error on small real audits when it was the outcome.
      
      
      No-go
      The audit-size planner. Its median error at the smallest audit was 11.3% to 16.8%, against a 10% limit. It is a documented calculation, not a validated tool.
      
    
      
  
      

  
      
    
      Limits
      
    
      What this does not show
      
    
      
      Not clinical, and not reviewed
      
      
        
      No dataset here is a patient-level clinical source-data audit. The Rwanda audit holds facility counts, and on ClinicalTrials.gov both values are sponsor-entered. Simulation data are synthetic.
      
        
      The methods are established, and no new statistical method is claimed. The package is not on CRAN, and it has had no outside peer review or clinical validation.
